## Read against 1.1.0

Written by hand after the run, because this release replaced the session
layer and the figures had every reason to move.

**The deterministic figures did not move.** Criterion 2 ordered 44.0 MiB in 44
pieces, the same as 1.1.0, 1.0.0, 0.9.0 and 0.8.0 — five releases now — and
criterion 1 ordered 104.0 MiB in 104 pieces, also unchanged. That is the
result worth having: a long-lived client that keeps holding public torrents
across runs (TOR-128) does not change what a run has to order, which was the
plausible failure this run existed to check.

**What moved is every non-deterministic figure, all in one direction.**
Arrivals fell — criterion 1's 101.5 to 92.0 MiB, criterion 2's 45.6 to 44.5,
criterion 6's 59.9 to 56.4 — and elapsed roughly doubled, 36.1 to 86.7s on
criterion 1 and 27.5 to 53.0s on criterion 2. Criterion 2's unclaimed arrivals
dropped from +1.6 MiB (3.7%) to +0.5 MiB (1.1%), and criterion 1's went
further negative, −2.5 to −12.0 MiB: more of what was ordered had not arrived
by the time the run ended.

The obvious candidate is TOR-150, which turned webseeds off in this release
after they panicked a client holding several torrents. The acceptance torrent
is served by archive.org over HTTP as well as by its swarm, so losing the
mirror should mean both fewer arrivals and a slower fetch — the shape of every
movement above, and the machine was LESS loaded this time (load 4.99 against
8.98), which makes the slowdown harder to blame on the machine.

**That candidate is not established, and one run cannot establish it.**
docs/tor-88-min-traffic-spread.md measured criterion 2's actual traffic at
45.5–54.6 MiB over 18 runs of an unchanged build, mean 48.8, sd 3.35. This
run's 44.5 MiB is below that observed minimum but only about 1.3 standard
deviations below the mean, which is unremarkable for a single sample. So the
honest reading is that the arrivals figure is consistent with webseeds having
contributed and equally consistent with ordinary swarm variance, and this run
cannot tell the two apart. Telling them apart needs the A/B that doc's own
method describes, run with webseeds on and off against the same swarm.

**Which ceiling governed: neither.** No run stopped. Both traffic figures came
in under criterion 1's 150 MiB and criterion 2's 60 MiB ordered ceiling, and
no client-wide roof was configured (core.DefaultRoof ships unlimited), so
nothing was stopped by either of the two limits this release now carries.

**Criterion 5 is the one that gained rather than kept its measurements**, and
it is why this run matters more than 1.1.0's. It was true by construction —
one client per run, privacy decided before the client existed — and this
release replaced that construction. It now measures the new one: a private
torrent attached while two public torrents fetched in the shared client, DHT
still off, on its own port (63842 against the shared client's 63839), and
refused outright when no port was left for a client of its own rather than
being put in with the public ones. Eight measurements where 1.1.0 had three.
